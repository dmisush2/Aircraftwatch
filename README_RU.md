# Aircraft Watch v72 — вариант для Netlify

Адаптировано из исходников v72, коммит 08b8d26e45e79a3a717ca2d584680b4946e5c7b1. Это отдельный вариант для Netlify, а не новая опубликованная версия ChatGPT Sites.

## Что сделать

1. Распакуйте архив. Загрузите его содержимое в корень вашего GitHub-репозитория. Сам ZIP загружать не нужно. Сохраните скрытые .gitignore и .env.example (на Mac: Command + Shift + точка).
2. Если ранее загружены файлы из старого архива, удалите из репозитория старые dist/, .openai/ и scripts/build.sh. Остальные одноимённые файлы замените файлами из этого архива. netlify.toml должен лежать рядом с package.json.
3. В Netlify укажите Base directory: пусто (корень репозитория), Build command: npm run build, Publish directory: public, Functions directory: netlify/functions. Удалите старое переопределение папки dist в настройках. Эти значения уже записаны в netlify.toml.
4. В Project configuration → Environment variables добавьте APP_USERNAME (придуманный логин), APP_PASSWORD (длинный уникальный пароль) и ADSB_RAPIDAPI_KEY (ваш ключ RapidAPI). Значения должны быть доступны Functions во время выполнения. Не записывайте реальные значения в GitHub или .env.example.
5. Запустите новый Deploy из GitHub. Откройте Netlify-адрес и введите заданные логин/пароль в окне браузера. Без APP_USERNAME и APP_PASSWORD сервер специально отвечает 503 с пояснением, а не открывает ваши настройки посторонним.

Для просмотра карты нужен API-ключ; без него оболочка приложения открывается, но API самолётов возвращает понятную ошибку. Хранилище Netlify Blobs подключается из Functions автоматически; старый Cloudflare R2 не требуется. Производственные данные отделены от preview-деплоев.

## Синхронизация и перенос данных

Зоны, список бортов и общие настройки сохраняются в site-wide Netlify Blobs с strong consistency и атомарной проверкой ETag. Данные переживают новые деплои того же проекта. Один Netlify-проект — одно общее пространство для всех устройств с этим логином; отдельных аккаунтов пользователей нет.

Старые данные R2 и localStorage другого домена не переносятся автоматически. При первом открытии нового домена настройте зоны/список заново либо используйте доступный в приложении импорт. На компьютере и телефоне открывайте один и тот же Netlify-адрес. Пароль и API-ключ не включены в архив. Доступ ChatGPT к старому сайту не является авторизацией для нового Netlify-сайта.

## Telegram и фоновый мониторинг

Сначала оставьте MONITOR_ENABLED=false. Для включения добавьте серверные переменные TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, затем MONITOR_ENABLED=true, и выполните новый Deploy. В самом приложении сохраните список регистраций, зоны, пороги и включите мониторинг.

Функция monitor запускается раз в минуту только на production. Она получает события исходного движка v72 и самостоятельно отправляет их в Telegram. Успешные доставки отмечаются в хранилище. После неудачи доставка повторяется; при редком сбое между отправкой и сохранением отметки возможен дубль. Короткие пересечения между минутными проверками могут быть пропущены. При большом количестве событий отправка продолжается в следующих запусках в пределах часовой истории событий.

Старый бот/cron Ramp Schedule не изменён. Пока старый Tracker продолжает отправлять уведомления, лучше использовать отдельного бота для Netlify или выключить один из двух мониторов, иначе возможны одинаковые уведомления от разных сайтов. Новый URL не подключается к прежнему cron автоматически. Около 43 200 проверок за 30 дней возможно при постоянном включённом минутном мониторинге; проверяйте квоты RapidAPI и Netlify. Кэш в serverless-процессах не гарантирует общий лимит запросов между экземплярами.

## Локальная проверка

Node.js 22+, npm:

```sh
npm ci
npm run build
npm test
```

public/index.html и lib/generated-worker.mjs генерируются сборкой. Для работающих API нужна среда Netlify Functions; простое открытие HTML не заменяет сервер. Деплой ZIP через статический drag-and-drop не подходит: используйте GitHub build или Netlify CLI с Functions.

Проверено локально: сборка, исходные тесты мониторинга/опроса/синхронизации, адаптер хранилища, авторизация и повторные доставки. Реальный production-деплой, доступ к вашему Blobs, RapidAPI и Telegram здесь не выполнялись и требуют проверки после настройки переменных.

Официальные справки: https://docs.netlify.com/build/data-and-storage/netlify-blobs/ и https://docs.netlify.com/build/functions/scheduled-functions/.
